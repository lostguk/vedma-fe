# Бизнес-логика — vedma-fe-new

## Аутентификация

### Схема авторизации

```
Регистрация:
  POST /register → email verification → POST /login → JWT token

Вход:
  POST /login → { token, user } → token в localStorage → user в AuthContext

Bootstrap (при загрузке приложения):
  localStorage.getItem('vedmino-token')
    → если есть: GET /profile → setUser
    → если нет или 401: loading=false, user=null

Выход:
  POST /logout → removeToken → setUser(null) → navigate('/')
```

### JWT Token

- Хранится в `localStorage` ключ `vedmino-token` (JSON-строка)
- Добавляется к каждому запросу: `Authorization: Bearer <token>` (request interceptor)
- При 401: автоматически удаляется (response interceptor)

### Регистрация

1. Пользователь заполняет форму в `LoginModal` (ФИО, email, пароль)
2. `POST /register` → бэкенд отправляет email для верификации
3. Пользователь переходит по ссылке из письма → `VerifyEmailPage` (`GET /verify-registration/:user/:hash`)
4. После подтверждения — вход через `LoginModal`

### Защита страниц

Только `ProfilePage` защищён авторизацией:

```jsx
if (!isAuthenticated) return <Navigate to='/catalog' replace />
```

Остальные страницы доступны без авторизации.

## Корзина

### Хранение

- `localStorage` ключ `vedmino-cart-v2`
- Формат: `[{ id, qty, name, price, old_price, image, slug }]`
- **Полные данные товара** хранятся при добавлении, чтобы корзина работала без API

### Добавление товара

```javascript
addToCart(product, qty)
```

- Принимает **полный объект** товара из API
- Проверяет `product.in_stock !== false` (не добавляет товар без наличия)
- Если товар уже в корзине — увеличивает количество
- Показывает toast с именем товара

### Очистка корзины

`clearCart()` вызывается **только** на `OrderSuccessPage` (после оплаты).
**Не** вызывается при создании заказа — иначе произойдёт редирект в каталог до оплаты.

## Оформление заказа (Checkout)

### Полный flow

```
1. Пользователь переходит в /checkout (если корзина пуста → redirect в /catalog)
2. Заполняет контактные данные:
   - Авторизованный: email и телефон readonly из профиля
   - Неавторизованный: все поля + пароль для регистрации
3. Вводит адрес (DaData, обязательно из подсказок)
4. Доставка: Почта России (автоматический расчёт через POST /shipping/calculate)
5. (Опционально) Вводит промокод → POST /order/calculate
6. Нажимает «Оформить заказ»:
   a. POST /order → создаёт заказ
   b. POST /payments → получает payment_url
   c. Redirect на payment_url (Альфа-Банк)
7. После оплаты банк редиректит на `/payment-success` или `/payment-error`. В URL бэкенд добавляет `payment=<public_id>` (и при передаче с фронта остаётся `order_id`, если был в `success_url` / `fail_url`).
8. Страницы `OrderSuccessPage` / `OrderErrorPage` при наличии `payment` вызывают `GET /payments/:publicId/status` (несколько попыток при «висящем» статусе). Только после подтверждения `paid` на успехе очищается корзина; при расхождении URL и факта (успех vs ошибка) выполняется редирект на правильную страницу.
9. Прямой заход на `/order-success` без `payment` — прежнее поведение: сразу `clearCart()` и праздничный экран без запроса статуса.
10. При ошибке создания платежа:
   - Баннер с текстом ошибки
   - Кнопка «Повторить оплату»
   - Кнопка «Оплатить позже» → clearCart() + navigate('/profile/orders')
   - Ссылка «написать в чат поддержки»
```

### Расчёт доставки

- Автоматически при подтверждённом адресе и непустой корзине
- `POST /shipping/calculate` с массивом `{ id, quantity }` + address
- Debounce: 500ms
- Парсинг: `data.PostOffice[0].service.total` → `Math.round(parseFloat(...))`
- Товары из категорий с `exclude_from_shipping` исключаются бэкендом

### Промокоды

- `POST /order/calculate` с items + promo_code
- Статусы: `applied` (применён), `not_exists` (не найден), `not_applied` (не применим)
- Автоматический пересчёт при изменении корзины (debounce 300ms)
- Один промокод одновременно

### Регистрация при заказе

Для неавторизованных:

- Дополнительные поля: ФИО, email, пароль, подтверждение пароля
- В `POST /order` передаётся `register: true` + `password`
- Бэкенд создаёт пользователя + заказ одновременно

## Товары и наличие (Stock)

### Поля товара

| Поле       | Тип         | Описание                                     |
| ---------- | ----------- | -------------------------------------------- |
| `stock`    | int \| null | Количество на складе. `null` = неограниченно |
| `in_stock` | boolean     | Есть ли товар в наличии                      |

### Логика отображения

- **ProductCard:** при `in_stock === false`:
  - Оверлей «Нет в наличии» поверх картинки (полупрозрачный фон)
  - Кнопка «Нет в наличии» (disabled, серая)
  - Тег и скидка не показываются
- **ProductPage:** при `in_stock === false`:
  - Вместо кнопки «В корзину» — текст «Нет в наличии»

### Логика бэкенда (для понимания)

- При создании заказа: `stock` уменьшается на количество заказанных единиц
- При возврате (refund): `stock` увеличивается обратно
- `stock: null` — товар/услуга без учёта (например, гадания, консультации)

## Категории и доставка

### Флаг exclude_from_shipping

Некоторые категории (например, «Услуги») помечены `exclude_from_shipping: true`.
Товары из таких категорий **не учитываются** при расчёте стоимости доставки.

Логика наследования: если родительская категория помечена — все дочерние тоже исключаются.

Это полностью серверная логика. Фронт просто отправляет все товары в `POST /shipping/calculate`, а бэкенд сам фильтрует.

## Профиль пользователя

### Табы

| Таб         | Путь                | Описание                                                   |
| ----------- | ------------------- | ---------------------------------------------------------- |
| TabInfo     | `/profile`          | Редактирование ФИО, телефон (маска), email, адрес (DaData) |
| TabOrders   | `/profile/orders`   | История заказов + оплата + повтор заказа                   |
| TabChat     | `/profile/chat`     | Список тем → создание → сообщения с вложениями             |
| TabPassword | `/profile/password` | Смена пароля (текущий + новый)                             |

### История заказов (TabOrders)

- Загружает `GET /orders`
- Статусы: new, payment_pending, paid, payment_failed, refunded, cancelled
- **Оплата:** для статусов `new`, `payment_pending`, `payment_failed` — кнопка «Оплатить» → `POST /payments`
- **Повтор:** для статусов `paid`, `refunded`, `cancelled` — кнопка «Повторить заказ»:
  - Очищает корзину
  - Добавляет товары из заказа в корзину
  - Redirect на `/checkout`

### Чат с админом (TabChat)

- Список тем → клик → тема с сообщениями
- Создание темы: заголовок + сообщение + вложения (jpeg, png, webp, pdf)
- Отправка сообщения: текст + вложения (multipart/form-data)
- Непрочитанные: badge в навигации (polling каждые 10 секунд)
- Lightbox для просмотра картинок-вложений

## Уведомления (Toast)

Используется `react-toastify`. Конфигурация в `main.jsx`:

```jsx
<ToastContainer
	position='top-right'
	autoClose={3000}
	newestOnTop
	closeOnClick
	pauseOnHover
	theme='colored'
/>
```

Паттерны использования:

- `toast.success('С возвращением, Анна!')` — при успешном логине (персонализированное)
- `toast.info('Вы вышли из аккаунта')` — при выходе
- `toast.error(getApiErrors(err))` — при ошибках API
- `toast.success('Товары добавлены в корзину')` — при повторе заказа
